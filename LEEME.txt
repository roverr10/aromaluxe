AROMALUXE - APP LOCAL CON BACKEND
=================================

Requisito: Node.js 18 o superior (https://nodejs.org).

PASOS
1. Descomprime esta carpeta.
2. Windows: doble clic en  iniciar.bat
   Mac/Linux: en terminal ->  ./iniciar.sh
   (o manualmente: npm install  y luego  npm run dev)
3. Se abrira el navegador en http://localhost:5173

`npm run dev` levanta DOS procesos a la vez:
  - API (Express + SQLite) en http://localhost:3001
  - Web (Vite) en http://localhost:5173
Vite redirige /api y /uploads hacia la API, asi que no necesitas abrir el puerto 3001.

DONDE SE GUARDAN LOS DATOS
- Base de datos: server/data/aromaluxe.db (SQLite)
- Imagenes subidas: server/uploads/
- Tu codigo fuente: src/App.jsx (y su copia src/App.tsx)

La primera vez que abres la pagina, el frontend siembra la base de datos con el
catalogo inicial. Despues, todos los cambios del panel de administracion se
guardan en SQLite. El carrito sigue en el navegador (localStorage).

USUARIOS
- Administrador: aromaluxe.catalogo@gmail.com / seccion2
  (se crea automaticamente la primera vez que arranca la API)
- Clientes: boton "Ingresar con Google". Sin Client ID funciona en modo
  demostracion (ingresas tu correo). La sesion se guarda en una cookie segura.

GOOGLE REAL (OPCIONAL)
1. Crea un Client ID en https://console.cloud.google.com/apis/credentials
2. Copia server/.env.example a server/.env
3. Completa GOOGLE_CLIENT_ID=tu-client-id.apps.googleusercontent.com
4. Reinicia `npm run dev`. El modal mostrara el boton oficial de Google y el
   token se verificara en el servidor con google-auth-library.
   Tambien puedes desactivar el modo demo con ALLOW_DEMO_AUTH=false.

CAMBIAR CREDENCIALES DEL ADMIN
Copia server/.env.example a server/.env y edita ADMIN_EMAIL / ADMIN_PASSWORD.
Si el administrador ya existe en la BD, cambia la contrasena desde el panel
(Modulo Usuarios) o elimina server/data/aromaluxe.db para empezar de cero.

COTIZACIONES Y CONTACTO
Cada cotizacion o mensaje de WhatsApp queda registrado en la tabla `leads`.
Para verlas: Panel Admin -> Administracion -> Cotizaciones.
Tambien estan disponibles como API en:
  http://localhost:5173/api/leads
Puedes abrir esa URL directamente: devuelve las cotizaciones en JSON sin
necesitar iniciar sesion (la aplicacion es local, solo localhost).

COMANDOS UTILES
- npm run build       -> genera la carpeta dist/
- npm run preview     -> sirve dist/
- npm run dev:api     -> solo la API
- npm run dev:web     -> solo Vite

Nota: no subas server/.env ni server/data/ a un repositorio publico.


=======================================================================
PRODUCCION (RAILWAY + SUPABASE)  <-- LA PAGINA PUBLICADA
=======================================================================
Railway solo publica el frontend estatico (no corre el backend Express).
Por eso, a partir de ahora la app usa Supabase para guardar TODO:

  - Catalogo, configuracion, banners, cupones, etc. -> tabla aromaluxe_kv
  - Fotografias de perfumes (estatica e interactiva) -> bucket aromaluxe-images
  - Cotizaciones y mensajes -> tabla aromaluxe_leads
  - Usuarios -> Supabase Auth (admin) + sesion local (clientes demo)

CONFIGURACION INICIAL (una sola vez)
1. Abre tu proyecto en https://supabase.com
2. SQL Editor -> New query -> pega todo el contenido de supabase/setup.sql -> Run
3. Authentication -> Users -> Add user:
     Email: aromaluxe.catalogo@gmail.com
     Password: seccion2
     Marca "Auto Confirm User"
4. Listo. Las claves ya estan en src/supabaseConfig.js.

COMO FUNCIONA
- La primera vez que se abre la pagina, el catalogo inicial se siembra
  automaticamente en Supabase. No hay que hacer nada mas.
- Cada cambio del Panel Admin se guarda en Supabase y lo ven TODOS los
  visitantes, no solo tu navegador.
- Las imagenes se suben al bucket publico y tienen URL permanente: ya no se
  pierden cuando Railway vuelve a desplegar.
- Acceso administrativo: aromaluxe.catalogo@gmail.com / seccion2
- Clientes: boton "Ingresar con Google" (modo demo). Para Google real,
  activa el proveedor Google en Supabase -> Authentication -> Providers.

EL BACKEND LOCAL SIGUE AHI
server/ sigue siendo el backend Express + SQLite original, pero el frontend
ya no lo usa. Queda como referencia para desarrollo local. `npm run dev`
sigue levantando ambos procesos sin problemas.

IMPORTANTE
- Supabase Free se pausa despues de 1 semana sin actividad. Con visitas a la
  tienda no deberia pasar; si pasa, entra a Supabase y clic en "Restore".
- NUNCA compartas la service_role key ni la contraseña de la base de datos.
  La publishable key de src/supabaseConfig.js es publica por diseno.
